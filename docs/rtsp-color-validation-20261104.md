# 2026-11-04 四路图像与 IMU 联合验证

验证时源码版本：Bridge `f7a1be8`，配套 SDK `51cdd94`。补测后仅将本记录并入原提交，运行代码没有改动。Bridge 自动测试 22/22 通过。

使用真实 4P 板卡、ROS 2 Humble、普通 USB TCP 端口转发和临时 IMU 转接。测试数据来自板上相机与 IMU，没有使用模拟视频或模拟 IMU。本次没有使用 USB 反向转发，也未手动修改 IIO 系统文件。

## 连续两轮实机结果

| 模式 | 第一轮四路图像帧数 | 第一轮 IMU | 第二轮四路图像帧数 | 第二轮 IMU |
| --- | --- | --- | --- | --- |
| `image_format:=bgr8` | 21 / 23 / 20 / 24 | 1271 组 | 22 / 20 / 22 / 20 | 1309 组 |
| 不传 image_format，使用默认 mono8 | 22 / 23 / 24 / 20 | 1771 组 | 20 / 22 / 22 / 20 | 1252 组 |

- 四路图像均为 1280×1088，检查了编码、步长、数据长度和 frame_id。
- 彩色模式四路均检测到颜色，默认模式为 mono8。
- 同时收到的 IMU frame_id 为 `orbvi_imu`，加速度和角速度数值均有限，加速度非零。
- 同一轮 `sensor_demo` 会话内还验证了 SDK 四路图像和 1000 组 IMU 联合接收；SDK 的 CRC、解析和序号间断错误均为 0。

每轮结束时正常退出 Bridge，然后向本次启动的 `sensor_demo` 发送 SIGTERM 并等待其退出，IIO 缓冲区均恢复为 0。两轮之间没有重启板卡。随后单独读取 200 组 IMU 也成功，退出后缓冲区仍为 0。

此前 `buffer is busy` 的补测阻塞已解除；本次没有复现，但此前残留状态的根因尚未确定。
